# Leesroutes referral allowlist

This package is a proposal for the existing production first-party measurement layer. It does not activate collection. Keep the historical `pr51-product-metrics` package unchanged.

First exercise the parallel `patch-test.sql` / `rollback-test.sql` package on the existing synthetic project `hlvujbrmfdlrfxdjwsmb`, setting that project ID as `lumiscore.metrics.release_target`. It is generated from the unchanged test installer, targets only `product_metrics_test` and the suffixed browser wrapper, and independently checks the full test function bodies. It cannot be applied with the production target guard. Synthetic traffic remains separate from production. Both target variants are exercised in PGlite.

Apply only after the technical release passes review and the deployed functions match the read-only baseline. The patch checks complete function-body MD5 values before every replacement and stops on drift. Set the existing release-target guard to `qvplwejffhjvxaypmjut` in the same connection before executing `patch.sql`. Confirm the compiled browser value and server runtime value of the existing `NEXT_PUBLIC_PRODUCT_ANALYSIS_ENABLED` switch, and the current consent endpoint behavior before deciding whether activation is needed. There is no separate server flag in the current code. Leave Leesroutes `analyticsMeasurementId` empty. Do not change activation merely to test this patch.

Only three existing functions change: `product_metrics.valid_context(jsonb)`, `product_metrics.record_event(uuid,text,jsonb)`, and `public.record_product_event_v1(uuid,text,jsonb)`. Their ACLs, invoker/definer properties and configuration survive `CREATE OR REPLACE` through `pg_get_functiondef`. No tables, policies, grants, triggers, endpoints or retention settings are added or widened. Existing confirmed taste rounds and saved-book transitions use the same source context.

The new context is exactly `source=leesroutes`, `medium=referral`, `campaign=none`. The browser accepts only the HTTPS origins `leesroutes.nl` and `www.leesroutes.nl`, or the complete fixed public marker `utm_source=leesroutes&utm_medium=referral&utm_campaign=leesroutes` without extra or duplicate UTM keys. Only enum values enter session storage and counters, after LumiScore consent. The marker is identical for everyone; it carries no identity, consent, title, guide path or visitor identifier. Destination canonicals remain clean. There is no Leesroutes collector or GA4 activation.

`referral_arrival` is a LumiScore document arrival under restored valid consent, once per document. A new acceptance never replays the earlier arrival. SPA navigation is not another arrival. Later consented actions can still carry the source while the marker/referrer is available. If consent is given only after a full navigation away from the landing page, attribution can be unknown: no marker is persisted before consent. Referrers can be absent and public markers can be copied, so attribution is an aggregate indication, not verified person-level provenance.

The report counts arrivals, page views, confirmed taste starts/completions and saved-book transitions with this source. It deliberately leaves source clicks and linked visitor conversion unavailable. Counts are events, not people or a joined cross-domain funnel. Blocked clients, denied/expired consent, DNT/GPC, delivery loss and retention limit coverage. Source clicks cannot be inferred from arrivals, and arrivals are not a valid denominator for a person-level conversion rate.

`rollback.sql` reverses the exact reviewed function-body changes and stops on drift. It preserves aggregate counters and product data. Disable the new browser emission first if rolling back the database. Keep the updated report reader until the new context/event rows have expired; an older reader rejects unknown rows.

Validation: `node --experimental-strip-types --test lib/product-metrics/contract.test.ts lib/product-metrics/browser.test.ts scripts/product-metrics-leesroutes.test.mjs`. The PGlite test installs the unchanged production fixture, exercises consent and DNT/GPC, rejects free text and forged browser conversion events, records real taste/save transitions, checks permissions, and restores the exact baseline. No hosted writes are performed by the tests.

Current references reviewed: [Supabase changelog](https://supabase.com/changelog.md) and [database functions](https://supabase.com/docs/guides/database/functions). The patch preserves the existing empty search paths and privilege model.
