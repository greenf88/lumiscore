Cause and fix
The detail header placed the avatar BEFORE language and theme controls. The 280px
account panel used absolute right:0 relative to that avatar, not the viewport.
The real component with a local synthetic signed-in state on /en/book/6 measured
left=-59.4, right=220.6 at 390px. There was no panel height cap or scroll container.
This affects every localized /book/[workId] using the same detail header, not only
Work6; /books/[workId] redirects there. The site header normally had the avatar at
the right and did not have that horizontal cause, but shared the height limitation.

The detail avatar is now rightmost, retaining normal DOM/keyboard order. Shared
panel geometry clamps its edges to the visible viewport with 12px margins; it
recomputes while open on resize, scroll, visual-viewport keyboard/zoom events and
avatar resize. The panel stays in the account root, so it needs no portal or focus
trap. Height is bounded and overflow scrolls. Escape restores avatar focus;
outside clicks and focus leaving the account close the nonmodal panel. Existing
name-save, preferences and logout handlers/authorization are unchanged.
