# Boekmatch — separate dev/Preview prototype

## Contract written before implementation

This is interest discovery, never a rating or read-status flow. Ten distinct interested/not-for-me choices complete a round; skips do not count. Undo removes the last choice, including a skip. A round offers at most eighty genuinely available, reliably classified books in the chosen interface language. Previously rated/read books and existing taste-test anchors are excluded. Existing approved v1 evidence only; no title/author/cover inference, unreviewed taxonomy or invented descriptions.

An interest vector is the mean of L1-normalized verified traits, signed +1 for interested and −1 for not-for-me, with three neutral prior choices. The advice ranks unchosen cards by that vector's weighted overlap; the existing LumiScore is only a small tie-breaker. At most one main advice is shown. A reason names a shared verified trait and its actual interested-choice support count. No positive shared evidence means an explicitly exploratory advice, never an alleged personal match. Fewer than ten substantive choices produce an honest interim result, not fabricated answers. No match percentages.

Signals live separately in versioned sessionStorage per verified user ID (or guest) AND language, containing only work IDs/decisions, prior seen IDs and a shuffle seed. They are not ratings, public recommendations or server database records, are never migrated on login, and disappear when the browser session ends or the user clears them. Reload can resume within that session. This prototype does not promise cross-device interest persistence. Restarts exclude previous round cards and advice, and fetch another bounded deck; exhaustion is honest. No automatic reuse of seen cards to achieve ten.

The page and deck API fail closed: production is always 404; dev/Preview requires the known localhost fixture or existing approved hosted synthetic project hlvujbrmfdlrfxdjwsmb. Unknown/prod targets are rejected. No production navigation, sitemap or enabled flag is added. The deck API is read-only/private no-store; raw own ratings are never sent to the browser. Only an explicit reading-list click may use the separately guarded wishlist POST, with own-user RLS and an atomic INSERT ... ON CONFLICT DO NOTHING: an existing status is never overwritten, including concurrent changes. Anonymous saving uses the existing guest wishlist only. No automatic guest-wishlist migration is triggered by Bookmatch.

Keyboard buttons support Enter/Space; left/right choose, down skips, Backspace undoes. Native pointer events recognize horizontal swipes but ignore predominantly vertical motion, preserving mobile scrolling. Buttons are always available; no gesture-only functionality. Covers use the existing fallback component; controls and copy work in NL/EN and Ink/Paper.
