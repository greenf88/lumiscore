3. Import execution review

New scripts/catalog-selection-postgres.mjs uses pinned dev dependency pg 8.23.1
and the SAME importSelection transaction used by the existing local harness.
pnpm adds only this client and its 13 dependency packages; no existing dependency
is upgraded. It also records four version-specific release-age exceptions (pg,
pg-cloudflare, pg-connection-string, pg-protocol), following this repository's
existing policy format. No global package policy or production setting is changed.
No migration is executed by this runner. No dotenv or linked project is loaded.
CATALOG_DATABASE_URL is supplied only in the process environment, never a CLI flag.

- Default: repeatable-read READ ONLY transaction, rolled back after generating plan.
- Explicit target file binds host, port, database, role, database OID and PostgreSQL
  system identifier. The live fingerprint is checked before and inside transaction.
- Remote connections require TLS with certificate verification. URL query-option
  overrides and unknown target fields are rejected. No credentials in target file.
- --apply additionally requires a reviewed dry-run file and its exact SHA-256;
  both target and input-manifest hash are bound. The live plan must match exactly.
- Single-client serializable apply; deterministic table locks before planning;
  lock/statement/idle transaction timeouts; parameterized values; rollback on error.
- Bigint IDs are parsed only within JavaScript's safe integer range (pg otherwise
  returns bigint as strings, which would break strict identity comparisons).
- No UPDATE/DELETE to existing Works, authors, editions or user data. No new editions.
- CLI errors suppress database details/credentials; only safe SQLSTATE is logged.
- A commit acknowledgement lost in transit is ambiguous: inspect the ledger with a
  fresh dry-run before resuming. Never blindly retry using a stale pre-import plan.
- An already applied V1 ledger with changed records fails closed. No silent revision
  of an existing installation; any such case requires a separately approved plan.

Unit tests cover endpoint/fingerprint rejection before callback, read-only default,
rollback, commit, parameter binding, bigint limits, frozen inputs and exclusions.
PGlite additionally proves whole-import rollback after a partial synthetic failure,
zero writes/row-version changes on repeat, restart persistence, public-role read/
write permissions, unchanged bibliography and synthetic user links. These checks
alone do NOT establish actual pg-driver, Auth/JWT or PostgREST behavior. The actual
full-stack evidence below now supplements, rather than relabels, those earlier tests.
