Oorzaak en kleinste reparatie
De echte server is Vinext 1.0.0-beta.3 / React 19.2.6 / Vite 8.0.13 / Nitro
3.0.260903-beta; Next 16.2.6 levert de compatibele API/types. De Vercel-projecthint
is nextjs, maar vercel.json zet framework op null en bouwt met pnpm build:vercel.
Op Vercel gebruikt vite.config.ts Vinext plus Nitro, Node 24.x, regio dub1.
Het bestaande next.config.ts was leeg. Vinext's ingebouwde html-limited-botregex
herkent Google-InspectionTool en Bingbot, maar niet de gewone Googlebot-string.
Daardoor streamen desktop, mobiel en Googlebot-UA metadata naar de body; de
inspectie-UA wacht op metadata in de head. Dit is in huidige productie herhaald.
De oorspronkelijke bytes en de uiteindelijke DOM hebben beide de verkeerde
plaatsing; een browser verplaatste deze tags hier niet alsnog naar de head.
Dit zijn UA-simulaties, geen geauthenticeerde bezoeken van Google of Bing.

next.config.ts gebruikt de ondersteunde htmlLimitedBots: /.*/ voor alle UAs.
Dit blokkeert alleen Metadata API-output tot de head compleet is; bestaande
Suspense voor optionele boekinhoud blijft streamen. Er is geen botinhoudsvariant.
app/book/[workId]/page.tsx wacht in generateMetadata niet meer op de optionele
externe coverpromise (tot 3500 ms). Alleen een direct beschikbare, opgeslagen
editiecover wordt als deelafbeelding gebruikt. Bij ontbreken daarvan blijft het
expliciete no-image-beleid gelden: geen willekeurige/homepage-afbeelding.
Dezelfde late coverpromise en beschrijving blijven in de zichtbare boekpagina
gebruikt. Afweging: een uitsluitend extern/later gevonden cover verschijnt niet
meer als OG/Twitter-image in die response; een opgeslagen cover blijft behouden.
app/layout.tsx laat de paginaroute de title beheren. Dit verwijdert de bestaande
dubbele title op onbekende 404-pagina's zonder de foutpagina of vormgeving te wijzigen.
Geen stylesheet, componentindeling, ranking, catalogus of meetlogica gewijzigd.

Nog ontbrekend hosted bewijs
De aangemelde browser en Vercel-connector werken. De lokale CLI geeft bij project
inspect echter forbidden / 'The request is missing an authentication token',
invocationId 3113d74c-c046-43c8-8595-ca87e6db2404. Zonder accepted auth bereikt een
HTTP-client de Vercel-authredirect, niet de applicatie. Een eerdere response met
'Login – Vercel' is uitdrukkelijk uitgesloten van applicatiebewijs. De browser
staat het view-source-protocol niet toe; die route is gestopt, zonder omweg.
Geen tijdelijke sharelink of protection-bypass gemaakt; beveiliging niet gewijzigd.
Daarom bewijst het hosted DOM nog niet de oorspronkelijke hosted bytes of HTTP-status.
De 302-authresponse had X-Robots-Tag: noindex; dit is platform/authgedrag, geen
onverwachte noindex in applicatiemetadata. De authenticated application-header
moet nog afzonderlijk worden teruggelezen. Vereiste stap: normale Vercel CLI-login
vernieuwen, zonder token in chat, en uitsluitend bestaande geautoriseerde toegang
gebruiken voor de vijf-UA-GETmatrix. Geen rechten uitbreiden of bescherming uitzetten.

dezelfde machine, dezelfde loaders, 2 seconden optionele bronnen. Warmup apart;
geen bewijs van een echte koude cache. Browserbezoeken n=3 interleaved per route.

880 ms. Boek mediaan TTFB 164 -> 223 ms; zichtbaar H1-frame 368 -> 433 ms; LCP
456 -> 524 ms. CLS boek 0 -> 0; home 0.000429 -> 0.000429. Kleine aantallen en
dev-ruis geven geen statistische productieconclusie; er is bescheiden lokale overhead.
HTTP boek/desktop: alle metadata ontvangen mediaan 2092 -> 111 ms; daarvoor zat
metadata in de body, dus geen geldige 'complete metadata-head'-tijd. Inspectie-UA:
head/H1 mediaan 2208 -> 174 ms; de optionele bron vertraagt de hoofdinhoud niet meer.
De volledige boekresponse wacht nog circa 2.1 seconden op optionele inhoud.
firstH1SourceMs is bronontvangst, niet paint. Het zichtbare-frame-probe gebruikt
twee animation frames en zichtbare afmetingen; LCP wordt apart geobserveerd.
